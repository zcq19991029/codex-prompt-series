# 新建大型项目初始化 Prompt

## 适用场景

用于创建一个没有既有 README、项目交接文档或项目专用 Skill 的新大型项目。

## Prompt

```text
我要创建一个全新的大型项目。

项目名称：
[填写项目名称]

项目目标：
[说明项目要解决的问题、目标用户和最终交付内容]

项目位置：
[填写项目所在目录；如果尚未确定，请先根据当前工作目录创建合适的项目文件夹]

这是一个全新项目，当前可能没有 README.md、项目交接.md、AGENTS.md 或项目专用 Skill。请先完成项目架构初始化，再开始编写功能代码。

一、先检查项目规则和环境

请先检查当前工作目录、父目录、AGENTS.md、README.md、项目交接.md、docs、skills、配置文件，以及当前使用的语言、框架、包管理器和构建工具。

如果父目录已有 AGENTS.md，请遵守它，不要覆盖或重复创建冲突规则。

如果当前项目没有适用的 AGENTS.md，并且这是一个需要长期维护的大型项目，请在项目根目录创建简洁的 AGENTS.md，只记录本项目的协作规则、目录边界、测试要求和文档更新要求。

二、先做项目分析

开始写代码前，请说明项目类型、主要用户、核心场景、必须功能、后续功能、技术栈、部署需求、主要风险、可复用的 Skill 和旧项目经验。

不要把代码、配置、素材或临时文件散落在父目录。

三、建立项目目录

在项目根目录按实际需要建立 src、app、public、assets、docs、scripts、tests、data、config、examples、tmp 等目录。只有确实需要项目专用 Skill 时才创建 skills。不要为了形式创建空目录。

四、创建项目文档

必须创建 README.md 和 项目交接.md。

README.md 是项目长期说明，至少写清项目用途、目标用户、核心功能、版本范围、技术栈、目录结构、安装、启动、构建、测试、部署、入口文件、外部依赖、数据来源、已验证内容和当前限制。不要写成聊天日志。

项目交接.md 是跨聊天工作状态，至少写清长期目标、当前阶段目标、已完成内容、真实状态、卡住的问题、已尝试的失败方法、下一步、关键文件、已验证和未验证内容、最近更新时间。

五、Skill 处理规则

先检查已有公共 Skill。可以复用就不要复制。只有确实需要项目专用 Skill 时才创建项目内 skills 目录。每个专用 Skill 都要说明用途、适用范围、输入、输出、示例和验证方法，并在 README.md 中登记。

六、初始化后先汇报

目录和文档初始化完成后，先汇报项目架构、创建的目录和文档、技术选择、可复用 Skill、第一阶段目标和需要确认的事项。确认架构后再实现第一阶段功能。

七、持续维护

项目功能、目录、运行方式或部署方式变化时更新 README.md；进度、卡点、下一步或验证状态变化时更新 项目交接.md；新增或修改专用 Skill 时同步更新 Skill 文档和 README.md。不要把未经验证的功能写成已完成。
```
