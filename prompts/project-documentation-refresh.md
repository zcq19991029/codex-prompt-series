# 长期项目文档重建 Prompt

## 适用场景

用于项目已经开发了较长时间，但 README 或项目交接文档只记录了最近内容、无法看出项目完整用途的情况。

## Prompt

```text
请对当前项目的 README.md 和 项目交接.md 做一次完整重建，不要只补最近几步。

先读取父目录 AGENTS.md、已有 README.md、已有项目交接.md，以及项目目录结构、入口文件、配置文件、启动脚本、主要代码、部署说明、测试记录和历史文档。

请根据实际文件还原项目全貌，不要只依赖现有文档。

一、重建 README.md

README.md 必须让第一次接触项目的人看懂：

- 项目完整名称和用途
- 要解决的问题、目标用户和适用场景
- 经历过的主要阶段
- 当前已经实现的完整功能
- 技术栈和运行环境
- 目录结构、入口文件和关键模块
- 安装、启动、构建、测试和部署方式
- 已完成的部署或发布记录
- 已验证、未验证和当前限制
- 外部服务、数据库、数据和素材依赖
- 后续发展方向

README.md 是长期项目档案，不要写成聊天日志。

二、重建项目交接.md

项目交接.md 记录当前工作状态，但要保留必要背景：长期目标、当前阶段目标、最近完成内容、真实状态、卡住的问题、已尝试但失败的方法、下一步、关键文件、已验证和未验证内容、最近更新时间。

三、历史信息要求

不要删除仍有价值的内容；已废弃功能标记为历史功能或已废弃；无法从当前文件确认的内容明确标记为未验证，不要猜测；多个版本、部署地址或迁移过程按阶段整理。

四、完成后报告

请说明项目完整用途、主要历史阶段、当前完成度、最重要的下一步、无法确认的历史信息，以及修改了哪些文件。检查 README.md 和项目交接.md 是否互相矛盾。
```
