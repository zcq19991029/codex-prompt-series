# 长期项目文档重建 Prompt

适用：长期项目的 README/交接不完整、只写最近内容、层级混乱或与实际文件不一致。先确定业务边界，再依据证据重建；与 01 初始化原则配套。

```text
请完整重建当前工作范围的项目文档，不只补最近几步；先确定项目层级，避免生成重复说明。

工作范围（可选）：
[独立项目路径 / 多子项目容器路径 / 指定子项目；未填写时根据当前目录判断]

目标与重点（可选）：
[例如还原完整用途、迁移后更新、厘清生图和复现边界]

一、识别层级与真实状态
1. 先读取适用上级 AGENTS、现有文档及实际目录，确定当前范围是独立业务项目、纯多子项目容器，还是某个子项目。
2. 子项目按业务职责、输入输出、运行/验收和独立进度划分；src、assets、docs、scripts、tests、tmp 等支撑目录不因名字就变成子项目。
3. 独立业务项目重建自己的 README.md 和 项目交接.md。
4. 纯容器父目录只维护 AGENTS.md 中的目录、边界、共用规则和交接原则；各业务子项目各自重建 README/项目交接，不再创建父级总 README 或总交接，不默认给子项目复制 AGENTS。
5. 只指定一个子项目时，不重写其他项目文档、不扫描其私有内容；涉及共用边界的确需修订才更新父级 AGENTS。
6. 根目录确有可运行产品或公共仓库分发职责时，其 README/许可/索引有真实用途，不能因“精简”直接删除。说明区别，不把纯容器规则套到所有仓库。
7. 项目边界或归属有实质歧义时，先核实可确定部分，再问必要问题；不为写文档擅自拆分项目、移动代码或修改部署。

二、用证据还原全貌
8. 检查相关入口、配置、依赖、主要代码、启动/构建脚本、测试记录、素材、部署说明和 Git 历史；按项目实际需要选读，不强行要求所有项目都有这些文件。
9. 对声明核对证据：文件存在、功能实现、测试通过、可见行为、部署上线是不同状态，不混写。
10. 不只依赖旧 README、交接或最近聊天；旧文档和记忆可帮助检索，但不能直接认定仍然有效。
11. 部署/版本/数据库等当前状态在任务允许且可查询时核实；无法访问或验证的标明来源、时间和未验证范围，不能将源码/构建通过写成线上或实物验证通过。
12. 不运行会改变业务数据的“验证”，不读取或公开密钥；文档中只说明依赖与配置方法。
13. 历史功能、版本、迁移和发布按已有证据整理。代码删除不必然证明上线功能退役；当前找不到文件不猜测搬迁位置。
14. 对仍有价值的历史说明保留必要事实；弃用功能明确标注，不把历史能力写成当前功能。无证据的历史标“未从当前文件或记录确认”，不补造时间、地址或结果。

三、重建每个业务项目 README
15. 让首次接触者理解名称、完整用途、目标用户、核心场景、当前职责和不属于它的职责、与其他子项目的输入输出关系。
16. 说明当前完整功能及状态、实际技术与运行环境、关键目录和入口、依赖/数据/素材来源、验收方法与限制；必要历史阶段仅保留帮助理解现状的部分。
17. 写出实际适用的安装、启动、构建、测试和部署方式，核对命令与入口。没有这些需求时简短说明不适用，不编命令或堆空章节。
18. 发布记录附可验证的版本/提交和证据；日期或地址无法确认时明确说明。公开链接和本地路径分别核对。
19. 后续方向只写已确定的范围或标候选，不把愿望当承诺。README 是稳定说明，不是聊天日志或逐次故障记录。
20. 架构说明、素材规则、目录和使用步骤优先合入该 README；不自动新建项目架构、规范来源、目录说明、资产 README 等辅助文档。
21. 独立且较长、工具必需或有单独维护价值的专项文档可保留，在 README 登记入口和用途。盘点 Skill 的真实原件、项目入口、共享安装入口及实际链接目标；按下列规则记录归属、来源、依赖和验证状态，不复制通用提示词快照。真实任务提示词和证据应保留。
技能存放与链接规则（创建或整理前先核对本机实际配置）：
- 产品专用技能：真实原件放在所属产品仓库的 .agents/skills/<技能名>/，随产品提交、更新和交接。
- 跨项目自创技能：真实原件放在统一维护的技能源码仓库（本机为“提示词系列”仓库）的 .agents/skills/<技能名>/，需要使用的项目在自己的 .agents/skills 下建立目录链接。
- 独立第三方技能：已有可靠源码仓库时保留其原件并链接；没有独立源码维护需求时，可将唯一安装原件保存在用户级 ~/.agents/skills/<技能名>/。先核对来源、更新方式和资源依赖，不覆盖本地定制。
- 用户级 ~/.agents/skills 是本机共享发现入口；已有 ~/.codex/skills 入口按实际环境保留兼容。自创原件已在仓库中时，用户级目录只建立链接，不复制文件。本机对应 C:\Users\25466\.agents\skills 与 C:\Users\25466\.codex\skills；这些绝对路径只用于本机，公共模板不得假定其他电脑使用相同用户名或系统。
- 系统内置和已安装插件提供的技能保持软件管理位置，不将插件缓存搬成自创原件。只在任务确有需要时创建技能、用户级安装入口或项目链接，不给每个新项目批量挂载全部技能。
- Windows 使用目录链接（Junction）或环境支持的符号链接，不使用 .lnk 快捷方式。链接整个技能目录，保持 references、scripts、assets 等相对路径；一个技能只维护一份真实文件。
- 在项目 README 登记技能名称、中文用途、原件所属仓库及相对路径、项目入口、必要依赖和本机链接目标；统一维护仓库 README 登记共用技能和已知使用项目，不另建重复索引文件。区分目录可读、环境发现、实际调用三个验证层次。
- 本机 Junction 不作为可移植源码提交；按路径加入适用的 Git 忽略规则，并在 README 说明换电脑后如何重建。项目专用真实技能文件正常提交。核对暂存清单，不能把链接目标的整份外部源码或私有资料带进仓库。
- 移动原件前确认所属项目、所有已知引用与授权；移动后修复链接并核对实际解析目标和相对资源。删除安装入口只移除链接本身，不递归删除目标。迁移跨电脑时重新安装或建立链接。

本次文档重建仅记录现状和位置建议，不因这些规则自动移动原件、重建链接或清理副本；只有本次任务已有明确整理授权时才实施，并先核对同名技能是否为不同版本、定制或独立用途。


四、重建各自项目交接
22. 每个业务项目独立记录长期目标、当前阶段目标、最近完成内容、真实状态、当前卡点、相关失败尝试、下一步、关键文件、已验证/未验证及更新时间。
23. 仅保留继续工作必要背景；已解决问题归入完成，不累积流水账。没有失败或卡点不编造。
24. 下一步必须针对这个子项目；下游复现等独立任务以自足任务包承接，写清源文件版本、路径、顺序、模板/素材、输出形式、验收与问题，不依赖上游整段聊天记忆。
25. 不共享一份跨业务动态交接，不要求每个任务或支撑文件夹自动拥有“项目交接.md”。

五、避免精简变成误删
26. 本次重建默认仅更新目标文档和确需同步的引用；发现已有重复文档先说明其用途和建议合并位置，没有清理授权时不直接删除。
27. 用户已授权精简时，先将有效说明/状态合入对应文档，删除明确重复文件并修复引用；操作前核实文件归属、绝对路径和目录链接目标。
28. 保留原始素材、成品、实际任务提示词、验收证据和 Skill 必需参考资源。未知文件不当垃圾；不为精简再建一整套备份说明或空归档目录。

六、检查、报告和后续维护
29. 核对 README、该项目交接、父级 AGENTS、实际文件和保留专项文档的一致性，检查路径/链接、命令、子项目边界和验证表述；无法运行的明确记录，不能假称全部通过。
30. 汇报重建覆盖的业务项目、各自用途与当前完成度、关键历史和证据、下一步、无法确认内容、修改/合并/删除文件及验证结果。
31. 功能、目录、运行或部署变化更新对应 README；进度、卡点、下一步及验证变化更新该项目交接；跨项目共用规则变化更新父级 AGENTS，不再次生成重复总文档。
```

默认文档分工：独立项目拥有 README/项目交接；纯容器拥有 AGENTS，各业务子项目分别拥有自己的 README/项目交接。公开模板仓库的分发索引按其真实用途保留。
